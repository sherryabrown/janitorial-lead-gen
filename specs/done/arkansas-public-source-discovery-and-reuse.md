# Arkansas public-source discovery and reuse

## Request that initiated this plan

> Create one manageable plan in `specs/todo/` for Arkansas public-source discovery and reuse. For a chat-initiated city or confirmed county request, distinguish genuinely new sources from registered sources that lack a verified method. Research official sources only where needed; save geographic scope, category, current URL or access steps, check timing, evidence, and a versioned method. Then run that method through the existing bounded capture → interpretation → persisted results → reviewed import workflow. Prove reuse on a second request without repeating source research or hardcoding the pilot geography. Keep SAM separate. Include regression tests, a live end-to-end verification, and truthful partial/blocked states. Exclude account signup, closed-source automation, schedules, UI changes, and automatic AI learning. Reconcile the stale deferred roadmap without reviving its 2A–2G batches. Ask me only for decisions that materially affect this plan.
>
> For every researched source, also check its official portal and API documentation. Record the agency or portal tenant, signup and developer URLs, whether public access, an account, approval, an API key, or payment is required, and which forecast/opportunity/award data each path offers. Save the evidence date, requirements, current access state, blocker, responsible party, and exact next action. Reconcile existing `procurement_registrations` records and the private access ledger before creating anything new. Make this handoff durable and private; never store credentials in public source records. **Do not submit signups or request credentials in this phase.** Test that the later signup workflow can resume from the saved record without repeating discovery or creating a duplicate account.

## Objective and boundary

For one bounded Arkansas pilot geography, turn a genuinely missing official **public** source into a saved, verified category method and use the normal known-source path to review and persist its results. A second request must reuse that saved method. Existing registered sources with missing or expired methods remain **method work**, not new-source discoveries. Continue runnable city, county, and state checks while a route has unresolved discovery. This is one build phase, not a new sequence of 2A–2G batches.

In scope: chat/CLI orchestration, public source identity and method registration, official portal/API reconnaissance, private signup handoff, tests, and live proof. Out of scope: signing up, signing in, applying for API access, sending messages or alerts, storing credentials, paying, schedules, app screens, automatic AI learning, exhaustive research of all registered sources, and changing the separate Arkansas-wide SAM path. A source that needs authentication may receive a researched access handoff but no false public category capability.

## Single-phase implementation

1. **Classify and research only the gaps.** Add one chat-facing CLI result for an existing confirmed request that groups route/category work as `verified_method`, `registered_method_missing_or_expired`, or `source_missing`. Exclude SAM. For `source_missing`, follow the Arkansas procurement skill to inspect a bounded set of official local agency pages and their linked procurement channels. Include independent public agencies based in the city. Check city, then county, then state without repeating research for working methods. Save official identity, agency/provider tenant, applicable geography, category, evidence URL/date, and a precise outcome even when no usable public method is found. A search result, directory, or entry page alone cannot become category coverage. Keep the pilot to one newly requested city or confirmed county and one genuinely new public source; choose the pilot from current official evidence, not a hardcoded source name in application logic.
2. **Persist a verified method and run it.** Reconcile source identity against `procurement_sources`, its coverage, prior request links, existing methods and local ledger. Register a new source only if no existing agency/tenant/source match; otherwise repair the registered method gap. Use the reviewed `register` package with fresh snapshot/schema, exact route geography, category, check timing, allowed official URL(s), bounds/terminal condition, parser version, expiry and verification evidence. If an official page links a changing artifact, save an evidenced link-selection rule rather than treating an old PDF URL as a current feed; implement that rule only if the pilot needs it. Test package/rollback/replay and read back the live row. Replan and run the existing known-source runner on the **same** request. A blocked fetch, malformed listing, login shell, missing linked document, or unconfirmed pagination stays partial/blocked, never zero. Do not broaden category or work-location claims.
3. **Interpret, persist and prove reuse.** Generate the normal interpretation packet from saved run hashes. Cite exact rows/pages and distinguish forecast, historical/open opportunity and executed award; review location and possible duplicates. Stage eligible findings as immutable intake, make explicit reviewed import decisions, test the exact package, apply under existing scoped authority, and read back leads/links/status/history. Select a pilot with a real relevant candidate when official evidence permits; if it has none, persist its evidenced zero or partial state and leave the live-import acceptance check open rather than manufacture a lead or widen the pilot silently. Create a second bounded request for the same geography (or a user-confirmed county request including that city), and show that the registered method routes and runs without a new source-research step or duplicate registration. Keep county selection confirmation per request. Unchanged captures must not duplicate intake or leads.
4. **Leave a durable signup handoff.** For each source researched in step 1, inspect official agency/provider portal and developer/API documentation. Save **observed** portal tenant, official signup/docs URLs, public versus account/approval/key/paid requirements, documented category access, endpoint/filter/pagination/quota information where available, checked date, evidence, access state, blocker, responsible party and exact next action; mark unknown facts unknown. Distinguish portal signup, email verification, agency approval, sign-in, document access, API application, credential issuance and verified API request. Reconcile existing `procurement_registrations` and the private ledger; never reset a pending/verified stage or submit a duplicate application. Add one narrowly scoped private database handoff table keyed by source plus portal/API tenant/channel, with service-role-only reads/writes and nonsecret evidence/history, or reuse an equally private existing structure only if inspection proves equivalent access controls. Link the existing registration ID when present; do not copy account email, secrets, verification links or mailbox contents. Add a read command returning the next signup action, and prove it reconstructs the handoff from the database alone after local ledger files are unavailable. No signup request is sent in this phase.
5. **Reconcile guidance.** Link this plan from the header of the deferred Arkansas roadmap, noting it supersedes only the old Phase 3 discovery/signup wording for this bounded public-source build. Keep its historical 2A–2G evidence untouched. Update `docs/KNOWN-SOURCE-EXECUTION.md` and the Arkansas skill references only where the tested command or private handoff changes their instructions; leave old observations dated rather than rewriting them as current proof.

## Tests and live acceptance

- Offline: city/county ordering and fresh county confirmation; exact `source_missing` versus registered missing/expired method; a working source cannot conceal another gap; independent city agency routing; no SAM geography job; duplicate provider/agency/tenant and cross-route source reuse; changed URL/expiry; blocked/partial/entry-only never becoming lead coverage.
- Offline: reviewed source/capability registration rollback and replay; evidence URL/hash and bound validation; same-request execution and second-request method reuse with no new discovery record; candidate identity/location/classification; unchanged capture no-op; reviewed import rollback, replay and protected user fields.
- Private handoff: official URLs and states round-trip without the local ledger, unknown/paid states remain truthful, existing pending/verified registration is preserved, same tenant cannot produce duplicate signup work, secret-like metadata is rejected, and anonymous/authenticated clients cannot read or write the handoff. Keep credentials out of fixtures and logs.
- Live: one bounded official public source is newly researched and registered or a registered gap is correctly repaired; method/capture/interpretation and any eligible reviewed import have database readback. A second request reuses the source method without research. Save IDs, exact URLs, query window, run/capture hashes, method version, counts, import receipt, unresolved items and private signup next action. If no eligible lead exists, report the exact incomplete live-import check and leave this plan in `todo/`; do not claim end-to-end completion from a synthetic lead.
- Run affected tests plus the repository `npm run check` gate once after implementation. Apply any migration through the reviewed deployment process and verify live access policy/readback. Preserve unrelated working-tree changes.

**Completion:** Move this plan to `specs/done/` only when the live source-to-reuse path, a real eligible reviewed-import readback, and the private signup handoff are evidenced. Otherwise keep it in `specs/todo/` with the specific acceptance check and external blocker named.
